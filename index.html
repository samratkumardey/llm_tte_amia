Abstract

From trial protocol to executable pipeline

Target trial emulation (TTE) enables causal inference from observational data but remains bottlenecked by manual, expert-dependent protocol operationalization. While large language models (LLMs) have advanced clinical knowledge extraction and code generation, their ability to automate end-to-end TTE workflows remains largely unexplored.

We present an LLM-driven framework using retrieval-augmented generation to extract the five core TTE design parameters from the Carotid Revascularization and Medical Management for Asymptomatic Carotid Stenosis Trial (CREST-2) protocol and generate executable phenotyping pipelines for real-world EHR data.

The framework was evaluated along two dimensions. First, protocol extraction accuracy was assessed against a gold-standard checklist of trial design components using precision, recall, and F1-score. Second, outcome validity was evaluated through population-level concordance analyses comparing EHR-derived outcomes with published trial endpoints using standardized mean difference, observed-to-expected ratios, confidence interval overlap, and two-proportion z-tests. Human-in-the-loop validation assessed the correctness of extracted clinical logic and phenotype definitions.

Together, these evaluations demonstrate a structured approach for assessing LLM-driven protocol-to-pipeline translation for scalable real-world evidence generation.

Framework · Figure 1

Three LLM modules, two human checkpoints, two execution pipelines

Each design parameter is extracted from the CREST-2 protocol by the LLM and mapped to executable analytic logic against the Oracle EHR Healthcare Data Model, with clinician and informatician review between generation and execution.

LLM-driven modules

  • RAG-augmented protocol parser extracts structured TTE criteria
  • Phenotype generator maps concepts to ICD-10-CM / CPT and writes code
  • Cohort analyzer interprets cohort and outcome distributions

Human-in-the-loop roles

  • Clinician in the Loop (CITL) checks eligibility, outcomes, code sets and the clinical plausibility of results
  • Informatician in the Loop (IITL) checks phenotype logic, data-model mappings and generated code

Execution pipelines

  • Modular phenotyping pipeline runs cohort assembly, outcome classification and event ascertainment at scale
  • Causal inference statistics produces the estimates compared with trial endpoints

      Discussion
      
What this shows, and what it does not

    

    

      
KEY CONTRIBUTIONS
        
A structured five-design-parameter template that forces every TTE component to be defined before code is generated.

        
A multi-model, HIPAA-compliant architecture that separates protocol reasoning from patient-level computation.

        
A vascular territory-specific stroke classification (anterior vs. posterior circulation) for finer outcome ascertainment.

      

      
LIMITATIONS
        
Evaluated on a single trial (CREST-2) and a single EHR data source.

        
LLM outputs are non-deterministic; generated code can vary across runs without strict version control.

        
No randomization or confounding adjustment, so comparisons with trial results are descriptive rather than causal.

      

      
FUTURE WORK
        
Cross-reference generated code sets against phenotype libraries such as PheKB and eMERGE.

        
Automated unit tests for temporal logic and code-set membership.

        
LLM-as-judge review of clinical plausibility, and simulation with synthetic EHR data of known event rates.
